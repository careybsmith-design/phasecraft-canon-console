# Creation loop (Phase 6)

- Prompt compilation is pure in `src/domain/creation.ts` and reads only typed fields; `creation_prompt_raw_guard` re-checks every stored prompt against the sources' captured text and hash. Why: Part 13.4 enforced twice, not by convention.
- Every write goes through `thread_compile_creation_prompt`, `thread_dispatch_build`, `thread_record_build_result`, `thread_record_skeleton`, `thread_record_iteration`, `thread_set_cost_ceiling` (service role only). `build_runs_guard` enforces platform clearance, the full reproducibility key, per-build/mission/cell ceilings and pinned fields. Why: ceilings at dispatch (13.5), lineage by system.
- The database records the run BEFORE the adapter is called, so nothing leaves THREAD unchecked.
- Live dispatch sends the THREAD run ID and binds the external ID through `thread_bind_external_build`; signed callbacks use `thread_receive_build_result` with row locking and a payload hash. Why: response races and retries cannot duplicate artifacts or change a finished result.
- Platform registry: `PLATFORM_REGISTRY` mirrors the `build_platforms` seed; `detectChangeClass` mirrors `_classify_iteration`; the simulated digest mirrors `_sim_build_digest`. Change both together.
- Adapter choice follows `adapter_bindings`; a live binding without an endpoint/token refuses before any run write, never falls back to simulation. Live results return via `/api/public/hooks/build/$platform` signed with `BUILD_WEBHOOK_SECRET_<P>`. Why: missing live configuration cannot masquerade as platform execution.
- L-08: THREAD stores only the platform's final `outcome` (`succeeded|failed|partial`) plus `mirrored_from`; the legacy `build_runs.status` column is deprecated and write-locked by `build_runs_status_lock`, and BuildRun objects use the `evidence_record` lifecycle. Never reintroduce execution status fields. Why: platforms own execution; THREAD owns lineage (AW-16).
